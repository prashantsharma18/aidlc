# Proposed platform changes

The framework does not edit the platform. These are proposals for the platform owner. `PC` is the
platform catalogue, `~/projects/enterprise-ai-platform/platform-catalog`.

The data itself needs no change. The collector's metadata allow-list already keeps every attribute
the catalogue and the alerts read (`decision`, `source`, `tool_use_id`, `hook_event`,
`num_non_blocking_error`, `num_cancelled`, `cost_usd`, `session.id`).

## 1. Alert rules

1. Copy `core/observability/alerting/aidlc.yaml` to
   `PC/lab/grafana/provisioning/alerting/aidlc.yaml`. The provisioning folder is already mounted.
2. Add a contact point for the `harness-owners` label.
3. Restart Grafana, following the platform repository's `docs/runbooks/lab-deployment.md`.
4. Check that both rules load: Grafana, Alerting, folder `aidlc`.

## 2. One dashboard panel

The platform's dashboards are generated by `PC/tools/grafana_dashboards.py`, and
`PC/tests/grafana/test_grafana_dashboards.py` pins the generated set. So the panel is added through
the generator, never as a hand-written JSON file.

1. In `PC/tools/grafana_dashboards.py`, add a "Guard denial rate" stat panel to `agent-flow`, in
   "Where the flow gets stuck". Use the `guard_denial_rate` query from
   `core/observability/metrics.yaml`, with the dashboard's `team=~"$team"` filter.
2. Update `PC/tests/grafana/test_grafana_dashboards.py` if it pins the panel list.
3. Regenerate the dashboards with the generator, and run the platform's tests.

This is the only panel the platform lacks. Every other metric in the catalogue uses an existing
panel, a query or another source.

## 3. Managed settings: tag events with the repository

`/etc/claude-code/managed-settings.json` sets `OTEL_METRICS_INCLUDE_REPOSITORY` to `1`. Anthropic
documents the value `true`, and on 2026-10-22 no event in Loki carried `vcs.*` attributes, not even
from a repository with an `origin` remote. Set it to `true`, start a new session, and check that its
events carry `vcs_repository_url_full`. The collector's allow-list already keeps `vcs.*`.

## Platform notes (observed 2026-10-20 to 2026-10-22)

- Loki's `/ready` answered 503 ("Ingester not ready") at times and `ready` at others. There is no
  runbook entry for it.
- `hook_execution_complete` is documented by Anthropic, with its `num_*` attributes. If it is
  renamed, the `hook_health` query and its alert need the new name.
- In the last 7 days, one session's list-price cost exceeded the proposed 5 USD threshold. Check
  the threshold against your normal sessions before you add a contact point.
