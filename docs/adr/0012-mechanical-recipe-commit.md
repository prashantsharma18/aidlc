## Context
A framework upgrade changes dependency versions across a project and rewrites test syntax (for example JUnit 4 to 5
imports). Core's gates forbid both: no new dependency without asking, never change an existing assertion, every
changed file inside the slice's MAY CHANGE. Without a narrow exception, every upgrade either stops at the first build
step or teaches the agent to bend the gates, which is worse.

## Decision
A mechanical recipe commit is allowed on these five conditions, all required:

1. Only a deterministic tool qualifies: run on the same code it gives the same diff, and a check re-runs it to prove
   that. The output of an AI agent never qualifies (for example GitHub Copilot app modernization); its changes are
   ordinary code under every gate.
2. The tool and its version are approved in the plan (the bundle's `RECIPE` field); "no new dependency without
   asking" applies to the tool itself.
3. The commit holds only the tool's output: the test count is the same before and after, and no assertion changes
   what it checks. `scripts/check_recipe_commit.py` checks the re-run and the count and lists every changed assertion
   line for the reviewer.
4. A person reviews it as its own commit, with the trailer `Recipe: <tool>@<version>`.
5. Everything after it (fixes, clean-up) goes through all the normal gates.

## Why this is the established way
Large-scale change processes review mechanical changes separately from hand-written logic and still require a human
approver: Google's large-scale changes are generated by tools, split into reviewable pieces and approved by a
designated reviewer; Chromium's Large Scale Changes process lets approved mechanical changes skip per-directory owners
but still needs a second person. The five conditions keep that shape and add a re-run proof.

## Consequences
- `aidlc-build` makes the recipe commit first, runs the recipe check and stops for review; `reviewer-compliance`
  checks the commit holds only what the bundle's `RECIPE` approved.
- .NET has little deterministic tooling today: the .NET Upgrade Assistant is deprecated in favour of an AI agent, and
  OpenRewrite's C# recipes come through Moderne under a proprietary licence (an organisation's decision). The
  `dotnet-modernize` factory ships its own small deterministic recipe; most of a .NET port stays under the full gates.
- The check script needs the repository's test-count command; a team writes it once, in AGENTS.md's Commands.

## Amended by ADR 0024 (2026-11-20)
- `scripts/check_recipe_commit.py` is removed. The same check runs with git (`aidlc-build`, step 5): in a
  temporary worktree at the commit's parent, run the approved recipe, stage everything, and
  `git diff --cached --stat <commit>` must print nothing; the test count is the same at the parent and at the commit.
  The session writes the result to the evidence file, and the compliance reviewer reads it.
