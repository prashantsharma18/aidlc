## Follow-up fixes (owner-approved, 2026-11-19)
Two fixes landed after the final fix wave (`290aab4`). The owner approved both.

Item 1: the AI review loads nothing the repository controls.
- Both review passes run with `--setting-sources user` and `--settings '{"disableAllHooks": true}'`. The official Claude Code docs confirm both flags.
- The restore step mirrors claude-code-action's documented base-branch list for every pull request.
- CODEOWNERS owns `.mcp.json`.
- `--strict-mcp-config` was deliberately not used. It is unverified whether it drops the action's own comment tool.

Item 2: a suppression may never get wider.
- Markers are parsed into family, scope and rules.
- An added marker is covered only by a removed marker of the same family that it does not widen.
- Class scope is read from the file itself.
- A removed closing directive (eslint-enable, pragma restore, pylint enable, c8 stop) is judged by simulating the head file.
- Lines are counted the way git counts them.
- Independent reviews ran four fix rounds on it.
- Known limits, documented in `check_slice.py` and `skills/aidlc-onboard/references/suppression-rules.md`: pylint block scoping, pylint symbolic versus numeric ids, and trailing pylint pragmas.
- `aidlc-onboard` now proposes each stack's linter rules against blanket and unused suppressions, on that reference page.

- The Stop hook inside a live Claude Code session.

  so the answer does not change what runs: either way it is the base branch's settings.

  the `code-review` plugin still loads; the action's own inline-comment tool is still available; and whether the base
  branch's `CLAUDE.md` is still read (the docs do not say).
