## Rulings
- The plan was already in git (commits `d621d4f` and `4cddd4c`), so Task 1 skipped the step that adds it. If wrong,
  the plan file is untracked, which `git status` would show at once.
- Commit trailers name the model that wrote the commit (as in Plan 24), not the plan's Opus line. If wrong, only the
  wording of trailers changes.
- Haiku and Sonnet wrote tasks by size, Sonnet reviewed tasks, and Opus reviewed Tasks 2, 6, 7 and 9 and the whole
  branch. If wrong, a task is re-reviewed on another model.
- Task 9: the no-clean-code grader looks for code that cleans (`.strip(`, `.replace(`, `re.sub(`, a function named
  `clean...`), not the word "clean", so a correct run that only names AC2's "clean" in a comment passes. If wrong, a
  wrong run that cleans by another call, such as `.lower`, passes this grader; the reply and no-clean-row graders
  still catch it.
- Plan item O1, who checks the route where the design's table is silent: D2 and C at Tier 1 are checked by the code
  owner at Merge, route G by the approver of `new-system.md`, and a sliced Tier 1 plan by its tech lead first. If
  wrong, a route is checked at a later or earlier stop than a team wants, and the tech lead moves the check by hand.
- Plan item O1, where the rules sit: the Merge row's Who cell carries "reads the decision log", and the rules for the
  route and the log are two paragraphs in the tiers file. If wrong, a reader looks in one more place, and the six
  copies change together.
- Plan item O1, the log's row and its evidence: a row's commit is named once the step is committed, and the evidence
  file gains a COMMITS line (and its fixture) so the compliance reviewer, which runs no command, can check it. If
  wrong, a row can wait for its commit, or the reviewer rates a row low for a hash it cannot see.
- Plan item O1, eval case 1 puts the unclear AC2 in slice 2 and asks the build to pick a meaning and log it. If wrong,
  a run could stop before it makes a call, and the grader would fail a correct run.
- Plan item O1, ADR 0027 stays proposed. If wrong, the words ship while the decision is unrecorded as accepted.
- Task 10 had no task review of its own: the final whole-branch review read the record, because the controller edits
  it after that review anyway. If wrong, a record defect is caught one step later.
- The story index's ROUTE line keeps its two bracket groups: a test on `main` pins its first part, and the point is
  readability only. If wrong, a team reads one template line twice.
