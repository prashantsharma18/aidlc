aidlc has a third kind of skill, workflow, and its first skill, `parallel-lanes`, with the `QUEUE.md` template. The
nine tracked stages release at their gate in a lane; the index has the value `waiting: <decision> by <who>`; a plan
may mark its slices independent, and each such slice is its own pull request in its own files. aidlc still ships no
script. Test changes: exactly the items the owner approved under "Needs the owner's decision" in the plan (the plugin
version test moves from 6.0.0 to 6.1.0), and no other existing assertion. The suite was 400 tests at the start and is
now 469.

## How it was checked
Each task was built from the plan's text, then reviewed before the next one began. Reviews were by AI reviewers (a
stronger model for Task 3, the new skill and its lock). Each review that found a problem was followed by a scoped fix
and a second look.

- Task 1 (ADR 0025 and the test file): approved. Every line matched the plan; no existing assertion changed.
- Task 2 (the workflow kind in the validator): the review found that the rule against doing-word names (ending in
  `-ing`) also blocked ordinary nouns such as `string-tools` and `ring-buffer`. The rule now needs three letters before
  `ing` and has a short list of allowed nouns (`ING_NOUNS`: string, spring). Two tests were added. Running names such
  as `running-lanes` are still blocked.
- Task 3 (the `parallel-lanes` skill): three rounds. The review found that the stacked-slice push could overwrite a
  person's commit. The lane now checks that `origin/<branch>` is an ancestor before it rebases, and pushes with
  `--force-with-lease --force-if-includes origin <branch>`. A claim fast-forwards to the remote branch, and only
  "already exists", "checked out" or "used by worktree" means a row is taken; any other claim error stops the lane. A
  lane given a row by its brief or a person ends if that row is taken; only a lane with no named row takes the next one.
  The push names its branch, so it does not fail with "no upstream". The coordinator hands a stage a person must start
  to the person, and lists the row as `needs <stage> started by <who>`.
- Task 4 (stage gates and the index): approved. The lane line sits in exactly nine stage Gates, and both story-index
  copies are identical.
- Task 5 (the plan's slices): approved. Four minor items were deferred to the final fix wave (DEPENDS ON must name an
  existing earlier slice with no cycle; slice 1 runs on the part's branch; a re-plan resets slice numbers; one wording).
- Task 6 (build, verify, review for slices): the review found that a slice's evidence path
  (`plans/<KEY>/slice-<n>/review-evidence.md`) was stated in one place only. It is now in every stage that writes or
  reads it and in both reviewer agents, with a test that pins it across them.
- Task 7 (onboarding): approved. The lanes' worktrees go in git's exclude file, and the one-clone rule is added to
  `AGENTS.md` only with the person's agreement.
- Task 8 (the four lane eval cases): the review built each scaffold and probed the graders. It found they could fail a
  correct run: quoted paths and chained commands slipped past the Bash patterns, and the coordinator case depended on
  when a sub-agent's report arrived. The graders now handle quoted paths and chained commands, and the case is
  independent of report timing. A new test runs right and wrong samples through every grader.
- Task 9 (docs and version): approved. The only existing test that changed is the plugin version, approved as V1.
  One minor item was deferred: the change list does not mention the 6.1.0 bump.
- Task 10 (this record): the two tests were written first and failed for lack of the file.
- Final review: still to come.

## For the owner
Accept or amend ADR 0025; run the four lane cases when a key or token is available.

The decisions you gave were applied as follows. The design approval (2026-11-21). O1, the middle option done pstack's
way: every stage and `parallel-lanes` keep `disable-model-invocation`, and a sub-agent lane reads skill files by path.
V1: aidlc 6.1.0. E1: `GATES` unchanged. O2: the plan's rulings.

One refinement to O2 needs your attention. The plan said a sub-agent sent to a stage it may not run records
`waiting: start <stage> by <who>`. Review showed that nothing ever cleared that state. It was replaced: the sub-agent
ends without writing state and reports, and the coordinator gives the person the start words. The intent is the same:
nothing runs, and the person is told.
