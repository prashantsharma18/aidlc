## How it was checked
Each task was built from the plan's own text, then reviewed before the next one started. The reviews found real problems, and each was fixed in a scoped round that was reviewed again.

- Task 2 (drift check): criteria were compared as a set of lines, so a deleted or reordered line passed. They are now compared by criterion ID. A check that could not run no longer reports a release as ready.
- Task 3 (merge state): malformed `gh` output crashed the script, and `gh` could wait for input. Both now fall back to git without waiting.
- Task 4 (gitignore): a broken marker, and repository names the script cannot use, are now refused.
- Task 5 (contract version check): a shallow clone without tags and a deleted contract both passed. Both now fail closed.
- Task 6 (contract pin check): a repository value in `SOURCE` could reach `git fetch` as an option. The reviewer reproduced a command running through `--upload-pack`. The fix validates the value, puts `--` before external input, limits protocols, cleans the git environment and bounds the run. About twenty bypass attempts then failed. The fixes were checked on git 2.43, where `ext::` is blocked.
- Task 7 (workflows): a pull request's own oasdiff config could loosen the breaking-change gate, and the pin job ran the pull request's copy of the script. The gate now reads no config from the pull request, and both jobs run the base branch's scripts. When the base branch has no script, both jobs skip the check and say so; neither runs the pull request's own copy (contract-check got this in the final fix wave). The oasdiff fix was confirmed on the real oasdiff 1.35.0 binary.
- Task 12 (people decide, the AI records): the review found no check-first rule and no rule for a check that disagrees with what the AI was told. Both were added, and the release gate now cites the change-management record.

Tasks 1, 8, 9, 10, 11, 13, 14 and 15 were approved, with minor items carried to the final fix wave. Task 15 was reviewed by the controller.

Final review: a review of the whole branch found no critical issue. Its fix wave landed every item it listed:

- The contract scripts: the version check fails on any shallow clone, even one with some tags. The pin check strips `GIT_COMMON_DIR` and `GIT_NAMESPACE`, compares the copy's name with `SOURCE` without case, bounds the wait after it kills a timed-out group, and refuses a repository URL that carries a password or token.
- The workflows: contract-check skips a pull request whose base has no script, the contract-pin job has a timeout, contract-check asks for up-to-date branches, and the `api-v*` ruleset restricts tag creation too, bypassed only by the publish job's identity.
- Who runs the online pin check: the repository guide names it; a person or the release stage runs it before a release until phase 2b; a moved tag stops the release. The compliance reviewer checks a pin move's tag commit and that a contract PINS item matches `SOURCE`; CODEOWNERS gives `contracts/` to the leads. A contract pin is written as the tag's `v<MAJOR.MINOR.PATCH>`.
- ADR 0023 leftovers: no "hand-marked" row; plan and build check first where they can; review re-checks an approval the branch rules dismissed; the remaining records have a how-confirmed slot; onboard step 0 is in short bullets; designing-apis forbids tagging an unmerged commit by hand.
- `story_status.py`: the dead `copied_lines` and its test are gone, and a criterion block with a line too few or too many "differs from the spec".

Reviews were by AI reviewers. The owner has not yet reviewed the code. The owner agreed the plan's open decisions on 2026-11-20: keep the merged row (written by the AI after checking), keep `--check-release` reading local clones until 2b, reword the spec-approval eval grader, and raise the version after 2b.
