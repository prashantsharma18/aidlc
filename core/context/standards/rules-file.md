# Standard: the repository rules file

`AGENTS.md` is the single shared rules file, loaded at the start of every session by every tool.
It is the only repository context paid for on every turn, so every line must change what the
agent does.

## Sections
1. **Map**: a compact project map and a pointer to `docs/codebase-map.md`.
2. **Commands**: exact commands, above all the one-command check (`aidlc check`).
3. **Standards**: concrete standards, each with a named exemplar to follow.
4. **Boundaries**: restricted areas, review requirements, when to stop and ask. Enforced rules
   carry "(CI also checks this.)" so the agent understands a block instead of routing round it.
5. **Tools**: what to use for what, and what never to call automatically.
6. **Where to look**: one-line pointers to decision records, procedures, owners.

## Every rule
Specific (names a path or command), testable (checkable from the diff or a command), stable,
with its reason when not obvious.

## What stays out
Task details (bundle), long reference material (pointer), anything temporary (ticket), secrets
and personal data (never), generic advice, what a formatter enforces, personal preferences.

## Budget and removal test
For each line: would removing it make the agent make a mistake on a real task? If not, cut it or
move it behind a pointer. Warn above 80 lines, fail above 200 (`aidlc check context-drift`).

## Tool files
- Claude Code: `CLAUDE.md` is generated by `aidlc render --tool claude-code` and contains
  `@AGENTS.md` plus the lines in `.aidlc/claude.md`. It must stay under 40 lines.
- Other tools: rendered by their adapter (see the adapter interface in the framework docs).
- Never two full copies of shared rules: they drift.

## Ownership
Code-owned; changed only by reviewed PR with the code that changes it; agents are denied edits
(`core/policy/permissions.yaml`); significant changes run the agent-configuration evals.
